## 遇到提示时

- **ALREADY_RUNNING**：使用现有进程，同一应用只运行一份；诊断与晨会模式互斥。
- **已经在某区有一行**：继续填写已有行，或删除本人行后换区添加。
- **只能保存或删除自己创建的那一行**：操作本人姓名的行。
- **该行已更新**：使用最新卡片上的按钮。
- **已排队**：等待本行变为普通文字及“编辑”，不要反复点击。
- **正在打开编辑**：等输入框出现后再修改；原文会保留。
- **这一行已有操作排队或正在保存**：该行尚未刷新，保留输入并等待；其他行仍可提交。
- **UPDATE_UNCONFIRMED / QUEUE_PAUSED / MEETING_NOT_READY**：结果尚未确认，本群队列保留；交维护者恢复，不删文件强行重发。其他群独立处理。
- **MESSAGE_SEND_UNCONFIRMED**：50 分钟内重启只重试同一请求；超时先核对群消息。
- **LOCAL_STATE_INVALID**：核对本机群配置和状态文件，不上传凭据或原始文件。
- **AI_CONFIG_INVALID / AI_DISABLED**：模型未启用，按本机明确标记规则提取；检查本机 AI 配置后重启。
- **AI_EXTRACTION_FAILED**：该条晨会已保存；若有上次实际交付则保留，没有则不显示该人员。修复后编辑并重新提交。

正式群2布局 v13 保持个人行输入/文字切换，将 `delivery_form` 改为 `delivery_summary`。未开启自动交付的群继续布局 v12 和共享交付操作，不发生整卡更新。个人编辑保留原文、递增 revision；提交成功关闭编辑。飞书整卡 200 元素限制包含 plain_text/lark_md，不能忽略文本描述；预算同时考虑输入、展示及 AI 汇总增长，触及上限时拒绝新增或超额提交，不让已接收内容静默丢失。20 是人数硬上限，实际还受整卡元素与字节预算限制。

保存时产生独立 submissionId；后台识别结果进入同群持久队列，应用前再次核对 submissionId。删除或重新提交后到达的旧结果会丢弃；打开编辑但尚未重提时仍可完成对上次提交的识别。每群模型请求顺序运行，与晨会更新队列分开，结果合入最新状态，不覆盖等待期间新到的请求。保存/删除个人行与汇总使用一次 [批量更新请求](https://open.feishu.cn/document/cardkit-v1/card/batch_update)，AI 返回只更新汇总组件，不重画其他人的输入框。

升级或改变群的自动交付开关需先停止，确认没有 pending、layoutPending、summaryPending 或 requests 再替换渲染代码，避免同一UUID重试不同布局。汇总显示升级只更新delivery_summary，使用独立的持久刷新意图与summaryVersion；未知结果保留summaryPending，重启重试同一意图。启动准备完成前暂停保存/AI worker，避免抢用卡片更新序号。v12代码备份在 `.local/meeting/code-backup-before-auto-delivery/`，此次占位修复前代码在 `code-backup-before-summary-cleanup/`；不能直接覆盖后清空状态。AI原始响应及证据片段不持久化。

`.local/meeting/` 仅当前 Windows 用户与 SYSTEM 可访问。状态按 `days/<应用与群的哈希>/<北京时间日期>/meeting-state.json` 独立保存。首次升级复制并核对原状态，保留原卡片、消息和两行记录；原文件作为历史备份，不再作为运行状态。不要删除该目录来“重新发送”。

发送 UUID、更新 UUID、递增序号和意图先原子保存再请求飞书。结果不明确或 UUID 冲突保持待确认，不冒充成功。各群单独处理失败；定时失败不盲目另建卡片，核对后重启从同一状态恢复。输出仅状态码与数量，不保留原始回调、完整 SDK 日志、回调 token 或通讯录。

并发处理采用每群/当天独立的 `requests` 队列，最多24项，先原子保存经过校验的提交字段，再回应“已排队”。同一目标只保留一个在途操作；入队时计算排队请求合计的行数及整卡容量。更新成功后重新读取最新状态，在一次原子保存中提交该行并移除对应请求，保留异步等待中新排入的其他请求。旧状态没有 `requests` 时视为空队列，已保存行无需迁移。

网络结果未知时停止本群队列，保留原更新 UUID/sequence 和全部后续请求。维护者双击 **STOP_MEETING.cmd**，确认停止后再双击 **START_MEETING.cmd**；当天恢复会先重试原意图，明确成功后才处理后续队列。若仍显示待确认，保留数据交维护者处理，不清空 pending、队列或状态文件。代码升级前备份在 `.local/meeting/code-backup-before-concurrency/`；有未完成队列时不可直接回退到不识别该队列的旧代码。

升级前代码在本机 `.local/meeting/code-backup-v0.3.0/`。旧程序不识别逐日状态，不能直接覆盖当前数据继续运行；回退先停止并核对当天消息与状态。原 START_TEST.cmd / SEND_TEST_CARD.cmd 仅用于历史模板诊断。

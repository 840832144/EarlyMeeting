# EarlyMeeting｜本机卡片回调测试

版本 0.1.1 · 2026-09-07 · 仅排障，不是完整晨会机器人。

保留现有应用与卡片，只验证本机长连接和 `card.action.trigger`。不保存员工内容，不发送、更新或替换公共消息，不启用 10:00 定时，不安装系统服务。Codex 完整开发保持暂停。

## 本次修正与当前状态

用户已反馈 v0.1 的 Node 检查、离线检查和依赖安装通过，连接阶段出现 `SDK_ERROR / UNCLASSIFIED`；未提供 `CONNECTED` 或真实回调通过证据。连接失败的根因仍未确定，不能据此判定为网络故障、凭据错误或 Node 版本问题。

v0.1 的日志只识别部分字符串，会漏掉 HTTP 状态、错误对象内的诊断信息及十位业务错误码。v0.1.1 修正这个诊断缺口，并通过官方 SDK 的 `httpInstance` 注入点观察原有长连接入口请求的结果，区分入口请求与 WebSocket 握手阶段。没有增加额外请求，没有修改代理、TLS、凭据、回调业务或 SDK 版本。

这次是诊断修正版，**不是已经验证能解决连接失败的修复版**。未知字段仍标为 `UNREPORTED`，不虚构根因。

## 第一步：更新原测试文件夹

先在旧测试窗口按 Ctrl+C，关闭旧窗口。解压 v0.1.1，把包内文件复制进原来包含 `START_TEST.cmd` 的文件夹，替换同名文件。保留原有 `node_modules` 和 `package-lock.json`；不要复制旧业务工程的 `.env`。

成功表现：双击 `START_TEST.cmd` 后，离线检查显示 43 组；SDK 版本仍为 1.73.3，原文件夹依赖完好时跳过安装。连接前会显示 `[PROBE_VERSION] 0.1.1`。

失败怎么办：仍显示 17 组或没有新版本标识，说明运行的是旧目录，先核对文件位置，不重装 Node、不关闭防火墙。

首次使用也可直接解压本包后启动；要求 Node.js 22 或更高版本。缺失 Node/npm 时按启动窗口提示安装官方 LTS；组织策略阻止时停止并联系管理员。首次安装 SDK 需要用户输入 Y，依赖只装在本目录。

## 第二步：重新连接并收集安全状态

按提示在本机隐藏输入同一应用的 App ID、当前有效 App Secret、指定测试群 CHAT_ID。只运行一份同应用的接收程序，不将凭据发到聊天或 Git。

成功表现：显示 `[CONNECTED]`。`[ENDPOINT_OK]` 只表示长连接入口返回成功，不等于 WebSocket 已建立。保持窗口打开，再配置回调。

失败怎么办：出现错误或等待 45 秒仍未连接，按 Ctrl+C 停止。只反馈从 `[CONNECT_STAGE]` 开始的状态行，不需要完整日志、原始错误对象、连接地址、标识或凭据。不关闭证书校验，不更换下载源，不删除现有应用。

| 输出 | 解释与下一步 |
| --- | --- |
| `phase=ENDPOINT` | 正在申请长连接入口；结合 HTTP 状态和业务错误码定位，不能只凭阶段下结论 |
| `[ENDPOINT_OK]` | 入口返回预期结构，但尚未确认握手成功 |
| `phase=WEBSOCKET` / `WS_HANDSHAKE_FAILED` | WebSocket 创建或握手阶段失败；不自动认定是防火墙，继续按诊断证据排查 |
| `http=...` / `code=...` / `network=...` | HTTP 状态、业务错误码、网络错误标识分别保留，未获得时标为 UNREPORTED |
| `RESPONSE_SHAPE_ERROR` | 返回结构不符合 SDK 预期；不回显响应正文 |
| `SDK_HTTP_UNAVAILABLE` | 本机 SDK 缺少诊断注入点；停止，不擅自升级依赖 |

SDK 某些分支只提供固定失败文字，没有底层错误对象；此时本包能保留失败阶段，但不能保证取得所有网络细节。错误提示不是完成状态。

## 第三步：连接成功后配置回调

在现有应用的「事件与回调 → 回调配置」中选择长连接，添加「卡片回传交互」`card.action.trigger`，保存；后台要求版本发布时按提示操作，不扩大权限范围。

成功表现：后台接受配置并显示该回调。失败时核对本机仍连接、应用一致；不要反复创建机器人，不必订阅整个群的聊天历史。

## 第四步：只用虚构内容测试提交

在指定测试群的现有卡片填写“连接测试”，点击提交。

成功表现：本机显示 `[CALLBACK_OK]`，点击者看到“回调测试已收到；本次未保存、未更新晨会记录”。原卡片不变化是本包设计边界，不是正式记录保存成功。

失败怎么办：`CALLBACK_BLOCKED` 表示群不符或缺少群标识；`FORM_EMPTY` 表示收到交互但没有表单字段。检查对应配置，不能扩大允许群或把按钮到达当成数据收齐。测试结束按 Ctrl+C，看到 STOPPED 后关闭窗口。

## 安全和回滚

凭据只临时传给子进程，不写入配置文件或命令参数；结束后恢复父启动器原有进程环境。仅允许输出固定诊断标签、受限数值和表单字段数量；不输出原始日志、HTTP 头/正文、连接票据、用户标识或填写内容。

启动入口仅给本次 PowerShell 进程设置执行策略，不修改持久策略，不申请管理员权限。无开机启动、系统服务或公网监听。回滚时停止程序，恢复旧测试包文件即可；不删除原有应用、模板、群消息或依赖。

## 检查、证据与交接

本次修改在 Node.js v22.16.0 通过语法检查和 43 组离线断言，覆盖原有回调限制、消息不更新、嵌套错误/HTTP 状态/十位错误码/证书标识、代理认证状态、异常响应、请求不增发、原始响应和异常不被篡改，以及敏感哨兵文本不泄露。

没有使用用户凭据、没有真实调用飞书、没有执行 Windows 启动器。准备环境公共网络 DNS 不可用，未在该环境安装或验证真实 SDK；本次以官方 SDK HTTP 注入点契约和模拟 HTTP 接口回归为依据，仍需用户本机验证。SDK 顶层版本保持 1.73.3，不升级依赖。

实现入口保持 `support/local-callback-test` / PR #2；main、PR #1、正式 Task、其他项目与生产调度不改变。下一动作是用户运行新版并提供脱敏诊断状态，随后按实际根因处理。真实回调通过后，再单独确认模板字段、按人/群/日期保存、并发合并与原消息更新的范围。

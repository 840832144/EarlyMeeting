# EarlyMeeting｜本机卡片回调测试

版本 0.1.0 · 2026-09-07 · 仅用于排障，不是完整晨会机器人。

## 这次只验证什么

保留现有「晨会记录」应用和卡片模板，在自己的 Windows 电脑启动一个官方 SDK 长连接客户端，验证群里点击卡片后，本机收到 `card.action.trigger`。

**不会保存员工内容，不会更新、替换或新发群消息，不包含定时任务，也不会恢复 Codex 完整开发。** 回调只返回明确的测试提示。请只在指定测试群使用虚构文字；不要让员工把它当成正式填报。

当前依据：User 报告已有发送成功；之前上传工程的 `code/main.js` 仅包含发送代码，没有接收处理。没有提供现有卡片的完整模板 JSON，因此本包不猜测输入字段映射、模板变量或成员名单。

## 第一步：解压并启动

将压缩包完整解压到自己选定的文件夹，例如桌面上的 `EarlyMeeting-Test`。双击 `START_TEST.cmd`，不要直接在压缩包里运行。

成功表现：窗口依次显示 `[NODE_OK]`、`[SELF_TEST_OK]`、`[SDK_READY]`。首次运行会询问是否从 npm 官方源安装飞书官方 SDK 和依赖；输入 Y 后只安装到本文件夹，不全局安装。

失败怎么办：没有 Node.js 时显示 `[NODE_MISSING]`；本包要求 Node.js 22 或更高版本。到 Node.js 官网下载当前 LTS 的 Windows 安装包，完成安装后重新双击。安装遇到权限或组织策略限制时交给本机管理员，不关闭防火墙、不关闭杀毒软件、不换不明源。出现 `[INSTALL_FAILED]` 时只反馈该行错误码，不上传原始 npm 日志。

官方 Node.js 下载入口：https://nodejs.org/en/download

## 第二步：只在本机填写连接信息

窗口会依次询问现有应用的 App ID、当前有效的 App Secret，以及指定测试群的 CHAT_ID。群 ID 沿用已成功发送测试卡片时的运行配置。三项均用星号隐藏；不需要 Webhook 地址，也暂时不需要卡片模板 ID。

成功表现：显示 `[CONNECTED] 已与飞书建立长连接`。这时保留窗口，进入下一步。`[STARTING]` 只代表开始连接，不代表成功。

失败怎么办：显示 `[CONFIG_ERROR]` 就重新启动并核对输入；45 秒还没有确认连接时显示 `[WAITING]`，或出现 `[SDK_ERROR]`。反馈这些状态行，不发送凭据、完整日志、连接地址或原始回调。不要因为连接失败就直接关闭防火墙或禁用 TLS 校验。

请只运行一份同应用的回调接收程序。本启动器会避免本电脑同时启动两份本测试脚本，但无法检查其他电脑或别的接收程序；测试前由维护者确认没有其他消费者。

## 第三步：配置卡片回调

确认本机显示 CONNECTED 后，在开发者后台打开现有「晨会记录」应用，进入「事件与回调」下的「回调配置」，选择使用长连接接收回调，添加「卡片回传交互」`card.action.trigger`，保存。后台若提示版本变更需要生效，再按后台要求创建版本、审核和发布；不扩大应用可用范围。

这次配置的是卡片回调，不是添加“接收群聊天消息”的事件。不需要申请读取整个群聊历史，也不需要填请求地址。

成功表现：后台接受长连接配置，订阅列表包含 card.action.trigger。

失败怎么办：提示尚未建立长连接时，先核对本机窗口仍在、应用是同一个、是否出现重连状态；不反复重建应用。不认识后台按钮时，只截回调配置区域，不截凭据。

## 第四步：用虚构文字测试一次

回到指定测试群，在已发送的卡片中输入“连接测试”，点击真正的提交按钮。不要反复点击网页发送功能产生多张模板。

成功表现：本机显示 `[CALLBACK_OK]`；点击者看到“回调测试已收到；本次未保存、未更新晨会记录”。若字段数大于 0，说明此次也带回了表单字段；本程序不显示字段名或填写内容。这个成功只验证回调到达和即时反馈，不代表群记录已经更新。

失败怎么办：

- 没有 CALLBACK_OK：核对 card.action.trigger 已生效、卡片按钮确实配置为回传交互，并检查本机是否仍显示连接正常。
- `[CALLBACK_BLOCKED]`：核对本机填写的 CHAT_ID 是否就是当前测试群。回调没有群标识时也会拒绝，不擅自扩大范围。
- `[FORM_EMPTY]`：按钮回调到了，但这次没有表单字段。下一步检查卡片的表单容器、输入字段和提交按钮配置，不把它当成“填写内容已收齐”。

测试完成按 Ctrl+C，看到 `[STOPPED]` 后关闭窗口。没有创建系统服务或开机启动项。退回原状态时，可停止本程序并取消此次新添加的回调订阅；不要删除现有应用、模板或群消息。

## 下一阶段，不在本包中实施

回调实测通过后，再根据现有卡片的脱敏模板 JSON 确认字段，补上“按群、日期和本人身份保存 → 合并所有人最新内容 → 更新原 message_id”，并验证并发填写、重复提交和输入隔离。没有模板 JSON，不能保证保持现有卡片结构正确更新。

工作日 10:00 定时要求保留；测试期不启用定时。原计划的 Codex 完整开发仍暂停，恢复需要单独明确，不从这个诊断包推导执行授权。

## 检查记录与限制

已在准备环境 Node.js v22.16.0 下通过语法检查与 17 组离线断言：输入校验、测试群限制、缺失身份拒绝、回调结构、表单字段有无、无卡片更新返回、测试提示、日志白名单、敏感示例不进入输出，以及不把 SDK 的一般 ready 日志误报为真实握手成功。

**没有在用户 Windows 电脑运行；没有使用用户凭据；没有验证真实飞书连接、后台保存、消息提交或客户端表现。** 准备环境访问 npm 超时，未完成真实 SDK 安装验证；首次安装需要在用户本机验证。SDK 顶层版本固定为 1.73.3；本包不附带 SDK 文件、node_modules 或完整依赖锁，首次安装将解析其传递依赖并生成 package-lock.json，尚不是生产可复现部署包。

## 安全与运行细节

应用信息仅由本机交互输入，临时传给子进程；脚本不把 App Secret 写入配置文件、命令参数或日志。退出时恢复原有进程环境变量。日志只输出固定状态文字、允许的数字/网络错误码及表单字段数量，不记录员工输入、标识、回调 payload、token、连接地址。

`START_TEST.cmd` 为本次 PowerShell 子进程设置 `ExecutionPolicy Bypass` 来运行本目录脚本，不修改用户或系统的持久执行策略。不请求管理员权限；企业组策略阻止时停止并交由管理员处理，不尝试规避。运行前可检查 start.ps1 和 probe.cjs，确认行为范围。

不要复制旧 project.zip 中的 .env 到本目录。不要把真实凭据、聊天标识、员工填写内容或运行缓存放入公共 Git。包内 `.gitignore` 是辅助措施，不能替代提交前检查。
